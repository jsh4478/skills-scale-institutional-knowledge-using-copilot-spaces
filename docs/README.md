# OctoAcme Project Management Process Documentation

## Overview
OctoAcme runs projects using a structured, iterative approach that prioritizes customer value, clear ownership, and measurable outcomes. Projects move from a lightweight Initiation (one-pager and stakeholder alignment) into Planning (backlog, estimates, Definition of Done), then Execution with continuous tracking, followed by Release & Deployment and Retrospective & Continuous Improvement. The docs in this folder capture roles, workflows, checklists, and communication patterns so teams can deliver consistently and onboard quickly.

## Project lifecycle at a glance
1. Initiation → validate business need, create a Project One-pager, secure stakeholder alignment
2. Planning → break work into shippable items, prioritize backlog, estimate, define Definition of Done
3. Execution & Tracking → deliver iteratively using the project board and daily standups; follow PR conventions and QA gates
4. Release & Deployment → run pre-release checks, stage verification, and have rollback plans ready
5. Retrospective & Continuous Improvement → capture learnings, convert into action items, and measure impact

## Quick reference: when to use each doc
- New to OctoAcme? Start with Project Management Overview and Roles and Personas.
- Starting a new project? Complete the Project One-pager from Project Initiation, then follow Project Planning.
- In active delivery? Use Execution & Tracking and keep the Risk Register updated.
- Preparing to release? Follow the Release & Deployment checklist.
- Project wrapping up? Run a Retrospective and move action items into the backlog.

## Key principles
- Customer-first: prioritize usability and customer value
- Iterative delivery: deliver small, testable increments
- Clear ownership: name a PM and Product Lead for each project
- Data-informed: measure impact and iterate based on evidence
- Psychological safety: encourage feedback and learning
